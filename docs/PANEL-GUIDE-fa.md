# راهنمای کامل پنل TunnelPannel

[صفحهٔ اصلی](../README.fa.md) · [جزئیات Mesh و API مالک](MESH-fa.md) · [منابع پروتکل‌ها](MESH-SOURCES.md) · [گزارش آزمون‌ها](MESH-VALIDATION-fa.md)

این راهنما مربوط به برنامهٔ اصلی `apps/api` و صفحات `apps/web` است. فایل‌های داشبورد قدیمی در `web/` و استک Docker قدیمی، مسیر نصب پیش‌فرض این نسخه نیستند.

## نصب و اولین ورود

دستور دقیق نسخهٔ تحویلی در [install-one-line.txt](../install-one-line.txt) قرار دارد. آن را روی سرور پنل با دسترسی root اجرا کنید. نصب‌کننده وابستگی‌ها، کاربر سرویس، دیتابیس و systemd را آماده می‌کند و پاسخ واقعی `/health` را بررسی می‌کند. اجرای دوباره، تنظیمات و کلیدهای موجود را نگه می‌دارد. تغییر محلی سورس را خودکار بازنویسی نمی‌کند.

پنل روی `127.0.0.1:8080` سرور گوش می‌دهد. روی کامپیوتر خود اجرا کنید:

```sh
ssh -N -L 8080:127.0.0.1:8080 root@YOUR_PANEL_SERVER
```

سپس `http://127.0.0.1:8080/mesh` را باز کنید. در نخستین نصب، توکن‌های نقش یک بار نمایش داده می‌شوند؛ آن‌ها را خصوصی ذخیره کنید. توکن نصب با رمز SSH سرور تفاوت دارد. نصب مجدد، توکن گم‌شده را از روی هش بازسازی نمی‌کند. کلید فضای مشتری را مالک پنل صادر می‌کند.

| صفحه | کاربرد |
|---|---|
| `/mesh` | ثبت سرورها، آزمون همهٔ جهت‌ها، انتخاب و اتصال دائمی، تقسیم بار و فیل‌اور |
| `/ranking` | بنچمارک متمرکز روی یک جفت سرور، رسیدها و رتبه‌بندی |
| `/topology` | طراحی یال‌ها و جست‌وجوی مسیرهای چندمرحله‌ای؛ نصب عملی انجام نمی‌دهد |
| `/docs` | مستندات تعاملی API؛ عملیات حفاظت‌شده به توکن نیاز دارند |
| `/health` | سلامت API و دسترسی دیتابیس؛ سلامت تک‌تک تونل‌ها را اثبات نمی‌کند |

کلید در حافظهٔ همان صفحه نگه داشته می‌شود. بعد از بارگذاری مجدد یا رفتن به صفحه‌ای دیگر، دوباره وارد شوید. خروج، کلید صفحه را پاک می‌کند؛ تونل‌های فعال روی سرور را متوقف نمی‌کند.

## ۱. افزودن و بررسی سرور

برای هر ماشین، نام مشخص، IP عمومی، کاربر SSH، رمز و پورت ورود را وارد کنید. در `/ranking` می‌توانید کلید خصوصی SSH و اثر انگشت ازپیش‌تأییدشدهٔ میزبان را نیز وارد کنید. پین اثر انگشت از طریق API هم پشتیبانی می‌شود. ثبت اولیه بدون پین، کلید مشاهده‌شده را ذخیره می‌کند؛ اتصال‌های بعدی باید با همان کلید تطبیق داشته باشند.

«بررسی و افزودن» ارتباط و قابلیت‌های میزبان را بررسی می‌کند. رمز پس از ثبت از فرم پاک و در دیتابیس با کلید نصب رمزگذاری می‌شود. برای نصب وابستگی‌ها، ساخت رابط، فایروال و systemd، کاربر مقصد باید root یا دارای sudo غیرتعاملی مناسب باشد. مشتری معمولی نمی‌تواند IP خصوصی یا رزروشده را به‌عنوان هدف SSH ثبت کند.

با تغییر رمز SSH، در `/ranking` همان نام و همان میزبان را با اطلاعات جدید ذخیره و دوباره بررسی کنید؛ شناسهٔ سرور حفظ می‌شود. تغییر رمز در سیستم‌عامل، رکورد رمزگذاری‌شدهٔ پنل را خودکار عوض نمی‌کند. خطای اثر انگشت را با خاموش‌کردن بررسی کلید حل نکنید؛ ابتدا تغییر واقعی کلید میزبان را بررسی کنید.

## ۲. آزمایش همهٔ مسیرها

سرورها را با تیک انتخاب کنید. برای `N` ماشین متفاوت، تعداد مسیرها `N×(N−1)` است؛ دو سرور دو جهت، سه سرور شش جهت و پنج سرور بیست جهت دارند. نتیجهٔ A→B جایگزین آزمایش B→A نیست. می‌توانید چند سرور ایران و چند مقصد خارجی را هم‌زمان ثبت کنید؛ هر جفت، نتیجه و گروه مستقل دارد.

روش‌ها را از «همه»، مجموعهٔ شروع پنج‌تایی، یا انتخاب دستی مشخص کنید. کاتالوگ ۱۰۸ شناسه شامل ۹۱ پروفایل و ۱۷ ترکیب مشخص است. شش نام سازگار قدیمی، روش اضافه محسوب نمی‌شوند. «قابل آزمایش» به معنی موفقیت روی هر شبکه نیست. [فهرست منابع و موارد کنارگذاشته‌شده](MESH-SOURCES.md) توضیح می‌دهد چرا t4 یک سامانهٔ PBX است و مفهوم t6 با مسیر WG/SIT موجود هم‌پوشانی دارد.

| پروفایل | کاربرد |
|---|---|
| NORMAL | انتخاب معمول؛ سنجش تأخیر، سرعت، بازیابی و پاک‌سازی واقعی |
| DEEP | اندازه‌گیری طولانی‌تر برای بررسی دقیق‌تر مسیرهای موردنظر |
| QUICK در `/ranking` | غربال اولیهٔ سریع با ترافیک واقعی؛ جایگزین رسید کامل پیشنهاد Mesh نیست |

آزمایش، نرم‌افزار و منابع شبکه را روی سرورهای انتخاب‌شده نصب می‌کند و ترافیک مصرف می‌کند. کامپایل بعضی موتورها ممکن است چند دقیقه طول بکشد. آماده‌سازی وابستگی از زمان‌گیری عملکرد روش جداست. بیشتر بودن تعداد روش‌ها و جهت‌ها، زمان و حجم آزمایش را افزایش می‌دهد.

«لغو آزمایش» درخواست لغو و پاک‌سازی منابع اجرای جاری را ثبت می‌کند. اگر ارتباط میزبان قطع باشد، پاک‌سازی ممکن است به اتصال مجدد نیاز داشته باشد. تاریخچهٔ نتایج و تلاش‌های ناموفق حفظ می‌شود. کنترل‌کننده، کار نیمه‌تمام را پس از راه‌اندازی مجدد شناسایی می‌کند و منابع ثبت‌شده را مصالحه و پاک‌سازی می‌کند.

## ۳. نتیجه، معیارها و پنج پیشنهاد

از تاریخچه یک اجرا را انتخاب و «مشاهده» را بزنید. کارت هر جهت، پیشرفت، تعداد گزینه‌های تأییدشده و پیشنهادها را نشان می‌دهد. در «کیفیت همهٔ روش‌ها و انتخاب بیشتر»، نتایج هر روش را بررسی کنید.

| معیار | تفسیر |
|---|---|
| تأخیر متوسط و p50/p95 | زمان نمونه‌ها؛ p95 رفتار قسمت کندتر نمونه‌ها را نشان می‌دهد |
| جیتر | میانگین قدرمطلق اختلاف تأخیر نمونه‌های متوالی؛ مقدار کمتر معمولاً یکنواخت‌تر است |
| افت درخواست | سهم پروب‌های ناموفق برنامه؛ آن را با افت بستهٔ ICMP یکسان فرض نکنید |
| سرعت | خروجی ترافیک متعلق به آزمایش؛ ظرفیت تضمین‌شدهٔ اینترنت مشتری نیست |
| بازیابی | زمان بازگشت ترافیک بعد از توقف و بازگرداندن سرویس یا حامل واقعی |
| CPU و RAM | وضعیت کل میزبان در زمان اندازه‌گیری؛ فقط مصرف همان موتور نیست |
| امتیاز | ترکیب معیارهای موجود؛ فرمول در [scoring.py](../orchestrator/benchmarking/scoring.py) است |

تأخیر HTTP از تایمر curl روی خود سرور خوانده می‌شود و زمان فرمان SSH را شامل نمی‌شود. مقایسه را بین پروفایل و مبنای اندازه‌گیری یکسان انجام دهید. نتیجهٔ امروز ممکن است با تغییر شبکه یا بار سرور تغییر کند.

یک روش برای پیشنهاد Mesh باید رسید موفق نصب، انتقال واقعی، بازیابی و پاک‌سازی داشته باشد و معیارهای معتبر ثبت کرده باشد. بین گزینه‌های واجد شرایط، ابتدا حامل‌های بیرونی متفاوت و سپس رتبهٔ کیفیت انتخاب می‌شوند. بنابراین پیشنهاد پنج‌تایی لزوماً پنج امتیاز عددی نخست جدول نیست. اگر کمتر از پنج گزینه واجد شرایط باشد، کمبود صریحاً نمایش داده می‌شود.

| وضعیت | معنی |
|---|---|
| PASS یک روش | مراحل موردنیاز همان آزمون با موفقیت اجرا شده‌اند |
| PASS کل اجرا | اجرای موفق، با مسیر قابل استفاده؛ الزاماً همهٔ روش‌ها موفق نشده‌اند |
| FAILED | نصب، انتقال، بازیابی، رسید یا پاک‌سازی شکست خورده است؛ دلیل را بخوانید |
| INCOMPATIBLE / BLOCKED | پیش‌نیاز یا قابلیت لازم موجود نیست؛ امتیاز ساختگی داده نمی‌شود |
| TIMED_OUT / CANCELLED | مهلت تمام شده یا لغو درخواست شده است |
| DEGRADED در رتبه‌بندی | داده وجود دارد، اما بعضی آستانه‌های کیفیت رد شده‌اند |

## ۴. انتخاب، ترتیب و فعال‌سازی

روش‌های تأییدشدهٔ همان جهت را انتخاب کنید و با جابه‌جایی زودتر/دیرتر، ترتیب را تغییر دهید. «ثبت انتخاب و ترتیب» فقط انتخاب را ذخیره می‌کند. «فعال‌سازی گزینه‌های انتخابی» منابع واقعی، اعضای آماده و ورودی SOCKS احرازشده را می‌سازد. انتخاب بیشتر از پنج تا سقف فضای مشتری ممکن است؛ سقف پیش‌فرض ده عضو است.

به تعداد بیشتر اعضا، پردازش، حافظه، پورت و نگهداری بیشتری نیاز است. تغییر تعداد، ورودی ثابت را سریع‌تر یا پایدارتر تضمین نمی‌کند. روش‌های UDP یا پروفایل‌های فاقد آداپتر خروجی TCP دائمی، در خروجی قابل‌نصب Mesh پیشنهاد نمی‌شوند؛ موفقیت بنچمارک آن‌ها همچنان در جدول باقی می‌ماند.

## ۵. اتصال‌های فعال و فیل‌اور

هر گروه، یک مبدأ و یک مقصد دارد. چند مقصد هم‌زمان، گروه‌های جدا و ورودی‌های مستقل می‌سازند. کارت گروه، وضعیت کنترل‌کننده، آخرین سلامت مشاهده‌شده، اعضا، عضو مرجع، حالت و شمار اتصال‌ها را نشان می‌دهد.

`APPLYING` یعنی ساخت یا بازسازی در جریان است. `COMMITTED` یعنی ساخت تمام شده؛ برای سلامت جاری، وضعیت مشاهده‌شده و نشان UP اعضا را هم ببینید. نبود مشاهدهٔ تازه با سالم‌بودن اشتباه گرفته نمی‌شود. `FAILED` ممکن است پاک‌سازی مجدد بخواهد؛ خطای ثبت‌شده را بررسی کنید. `STOPPED` یعنی پاک‌سازی متعلق به گروه تمام شده است.

در حالت «اولویت و فیل‌اور»، اتصال جدید از نخستین عضو سالم با رعایت اولویت، پین و زمان انتظار عبور می‌کند. پروب واقعی nonce از همان مسیر، سلامت را بررسی می‌کند. پس از رسیدن شکست‌ها به آستانه، عضو ناسالم کنار گذاشته می‌شود. فاصلهٔ پیش‌فرض پروب دو ثانیه، مهلت پنج ثانیه و آستانه سه شکست است؛ زمان واقعی جابه‌جایی به پاسخ و مهلت پروب‌ها بستگی دارد.

اتصال TCP برقرار، هنگام خرابی به تونل دیگر منتقل نمی‌شود؛ برنامه باید دوباره متصل شود. خرابی کامل مقصد، با پنج پروتکل به همان مقصد پوشش داده نمی‌شود. برای تحمل خرابی مقصد، مقصد دیگری و سیاست انتخاب خروجی در برنامهٔ مصرف‌کننده لازم است.

## ۶. تقسیم بار و اولویت دستی

از «حالت اتصال»، «تقسیم اتصال‌ها بر اساس کیفیت» را انتخاب و «اعمال حالت و اولویت» را بزنید. وزن اولیه از سرعت، افت درخواست و جیتر اندازه‌گیری‌شده ساخته می‌شود. کیفیت پروب جاری، تأخیر، جیتر و شکست‌ها، وزن مؤثر را تعدیل می‌کنند. انتخاب بر اساس کمترین اتصال فعال نسبت به وزن است؛ اتصال در حال برقراری هم رزرو می‌شود و پس از بسته‌شدن آزاد می‌شود.

عضو ناسالم اتصال تازه نمی‌گیرد. پین دستیِ سالم، بر انتخاب خودکار اولویت دارد؛ «اولویت خودکار» آن را پاک می‌کند. شمار «فعال» وضعیت جاری و شمار «کل» اتصال‌های تخصیص‌یافته از زمان شروع همان پردازش درگاه است؛ ری‌استارت درگاه شمارنده‌ها را از نو آغاز می‌کند.

تقسیم بار بین اتصال‌های TCP جدا انجام می‌شود. این قابلیت bonding یا تقسیم بسته‌های یک دانلود تک‌اتصالی نیست. روی یک لینک یا CPU مشترک، تقسیم بار حتی ممکن است سرعت مجموع را کمتر کند. در آزمون دو سرور این نسخه، صحت داده و توزیع اتصال تأیید شد و افزایش سرعت در هر دو جهت حاصل نشد؛ اعداد واقعی در [گزارش اعتبارسنجی](MESH-VALIDATION-fa.md) آمده‌اند.

## ۷. خروجی، بازسازی و توقف

«نمایش خروجی» اطلاعات SOCKS گروه را برای نقش مجاز نشان می‌دهد. ورودی پیش‌فرض روی loopback مبدأ است. برنامهٔ مصرف‌کننده باید به همان ورودی دسترسی داشته باشد؛ مثلاً از روی مبدأ یا از طریق SSH forward. این خروجی به‌تنهایی مسیر پیش‌فرض تمام سیستم را تغییر نمی‌دهد و VPN سراسری IP/UDP نیست.

در «تغییر تعداد، ترتیب یا بازسازی اتصال»، نام روش‌های اندازه‌گیری‌شدهٔ همان جهت را به ترتیب و با ویرگول وارد کنید. بازسازی، منابع گروه را دوباره می‌سازد و پورت، نام کاربری و رمز ورودی را نگه می‌دارد؛ نشست‌های TCP باید دوباره متصل شوند. پورت ثابت پیش از تخصیص اعضای تازه رزرو می‌شود تا یک عضو SSH آن را مصرف نکند. اگر شنونده‌ای متعلق به دیگران پورت را گرفته باشد، بازسازی با خطا متوقف می‌شود.

«توقف و پاک‌سازی» سرویس‌ها، پورت‌ها، قوانین فایروال و منابع متعلق به همان گروه را جمع می‌کند. تاریخچه باقی می‌ماند. سرویس‌ها و رابط‌های متعلق به دیگران نباید حذف شوند. برای GRE/IP6GRE/IPIP/SIT بدون کلید بین یک جفت آدرس بیرونی، حامل مشترکِ تحت مالکیت تا خروج آخرین مرجع حفظ می‌شود؛ این اشتراک، مسیر فیزیکی مستقل ایجاد نمی‌کند.

## ۸. بنچمارک تک‌جفت `/ranking`

با توکن همان فضای موردنظر وارد شوید. این صفحه ثبت و به‌روزرسانی سرور با رمز یا کلید خصوصی، پین میزبان، بررسی قابلیت‌ها، انتخاب مبدأ/مقصد، روش‌ها و QUICK/NORMAL/DEEP را فراهم می‌کند. تاریخچه و «نمایش نتایج» اجرای قبلی را باز می‌کند. جدول، مرتب‌سازی، علت شکست و جزئیات/رسید را نشان می‌دهد.

«Save selection for failover» فقط انتخاب را ذخیره می‌کند. بخش قدیمی Failover Group، رابط سیاست قدیمی است؛ برای ساخت خودکار اعضای آماده، تقسیم اتصال و ورودی واقعی دائمی از `/mesh` استفاده کنید. انتخاب در این دو روند را با استقرار موفق یکسان فرض نکنید.

## ۹. طراحی توپولوژی `/topology`

با کلید فضای خود به این صفحه هم وارد شوید. شناسه و نام سرورهای همان فضا نمایش داده می‌شود. برای یال، شناسهٔ مبدأ، مقصد و نام روش را وارد و «Add / افزودن» را بزنید. یال جدید `UNTESTED` است. در فرم یافتن مسیر، مبدأ و مقصد نهایی را مشخص کنید؛ جست‌وجو محدود و بدون حلقه است.

مسیرهای `PLANNED` طراحی‌اند. تأخیر و ظرفیت مشتق‌شده، در صورت داشتن معیار یال‌ها از آن‌ها محاسبه می‌شود؛ جای اندازه‌گیری انتها‌به‌انتها را نمی‌گیرد. دامنه‌های خرابی مشترک نشان می‌دهند که دو مسیر ممکن است از یک سرور یا جزء مشترک بگذرند. این صفحه خودکار یک شبکهٔ چندپرشی واقعی نصب نمی‌کند. اعتبارسنجی فیزیکی این تحویل، دو سرور دارد؛ مسیر واقعی سه‌سروری یا ایران باید جداگانه آزموده شود.

## ۱۰. نقش‌ها، مشتری‌ها و فروش آینده

| نقش/کلید | دسترسی |
|---|---|
| SUPER_ADMIN نصب | دادهٔ مالک و مدیریت ساخت، سقف، غیرفعال‌سازی و چرخش کلید فضاها |
| OPERATOR نصب | عملیات مجاز پنل در فضای مالک؛ مدیریت فهرست مشتری‌ها را ندارد |
| VIEWER نصب | خواندن؛ عملیات تغییر و اطلاعات محرمانهٔ خروجی را نمی‌گیرد |
| کلید مشتری | مدیریت فضای مستقل خودش در سقف تعیین‌شده؛ داده و فهرست مالک را نمی‌بیند |

مدیریت مشتری‌ها فعلاً API دارد؛ صفحهٔ پرداخت یا ثبت‌نام عمومی ساخته نشده است. مسیرهای ساخت فضا، چرخش کلید، غیرفعال‌سازی و سقف‌ها در [MESH-fa.md](MESH-fa.md#مدیریت-مشتری-و-اتصال-آینده-به-فروش) مستندند. وب‌سایت فروش آینده باید بعد از تأیید پرداخت، با هویت مالک فضا را ایجاد یا سقفش را تغییر دهد و کلید مالک را فقط سمت سرور نگه دارد.

برای نمونه، پس از تنظیم خصوصی متغیر `TP_OWNER_TOKEN`، یک فضا بسازید. پاسخ حاوی کلید مشتری است؛ آن را در لاگ یا مخزن عمومی قرار ندهید:

```sh
curl -fsS http://127.0.0.1:8080/api/workspaces \
  -H "Authorization: Bearer $TP_OWNER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"customer-1","limits":{"max_nodes":4,"max_tunnels_per_route":10}}'
```

غیرفعال‌کردن کلید مشتری، درخواست API بعدی را می‌بندد و سرویس‌های systemd موجود را متوقف نمی‌کند. اگر پایان اشتراک باید اتصال‌ها را هم قطع کند، سیستم فروش باید صریحاً گروه‌ها را متوقف کند. ورود عمومی به دامنه، TLS، درگاه پرداخت و سیاست اشتراک به تنظیمات و اتصال جدا نیاز دارند.

## ۱۱. نگهداری، پشتیبان و بازیابی

```sh
sudo systemctl status tunnelpannel-api
curl -fsS http://127.0.0.1:8080/health
sudo journalctl -u tunnelpannel-api -n 100 --no-pager
sudo bash /opt/tunnelpannel/scripts/backup.sh /private/path/panel.tar.gz
sudo env RESTORE_TUNNELPANNEL=YES_I_UNDERSTAND bash /opt/tunnelpannel/scripts/restore.sh /private/path/panel.tar.gz
```

پشتیبان شامل دیتابیس مالک، فهرست فضاها و دیتابیس مشتری‌ها با فهرست SHA-256 است. فایل `/etc/tunnelpannel/tunnelpannel.env` و کلید رمزگذاری نصب را جداگانه و خصوصی نگه دارید؛ آرشیو آن‌ها را شامل نمی‌شود. دیتابیس رمزگذاری‌شدهٔ یک نصب، بدون کلید متناظر در نصب دیگر قابل استفاده نیست.

بازیابی، هش کلیدهای مشتری را هم به زمان گرفتن پشتیبان برمی‌گرداند. اگر پس از آن کلیدی چرخانده یا باطل شده بود، پس از بازیابی دوباره وضعیت دسترسی را بررسی و در صورت نیاز کلید را بچرخانید؛ کلید قدیمی ممکن است دوباره معتبر شود.

ارتقا را با دستور پین‌شدهٔ نسخهٔ موردنظر انجام دهید. پیش از ارتقا، پشتیبان بگیرید. حذف با `sudo bash /opt/tunnelpannel/scripts/uninstall.sh` برنامهٔ پنل را حذف می‌کند و تنظیمات، داده و منابع شبکهٔ نامرتبط را حفظ می‌کند. حذف پنل را با درخواست توقف همهٔ تونل‌های متعلق به مشتریان یکسان فرض نکنید.

## ۱۲. رفع خطاهای متداول

| نشانه | بررسی و اقدام |
|---|---|
| 401 | کلید صفحه خالی، قدیمی، چرخانده یا غیرفعال است؛ دوباره با کلید معتبر همان فضا وارد شوید |
| 403 | نقش برای عملیات کافی نیست؛ کلید مشتری به مدیریت مالک دسترسی ندارد |
| 409 | آزمایش/کنترل‌کننده مشغول است یا سقف فضا پر شده؛ وضعیت کار قبلی و محدودیت را بررسی کنید |
| Authentication failed | رمز/کاربر/پورت SSH و رکورد ذخیره‌شدهٔ پنل را بررسی کنید |
| Host key mismatch | تغییر کلید میزبان را مستقل تأیید کنید؛ پین را کورکورانه حذف نکنید |
| هیچ پیشنهاد یا کمتر از پنج پیشنهاد | دلیل حذف، پیش‌نیازها، رسید و قابلیت خروجی TCP را بخوانید؛ نتیجهٔ موفق ساخته نمی‌شود |
| سلامت مشاهده نمی‌شود | دسترسی SSH کنترل‌کننده، تازگی فایل وضعیت و پردازش درگاه را بررسی کنید |
| پاک‌سازی لازم است | ارتباط میزبان را برگردانید و توقف/بازسازی همان گروه را اجرا کنید؛ حذف عمومی رابط‌ها نزنید |
| سرعت کمتر در حالت تقسیم بار | پین را پاک و وزن‌ها، CPU/RAM و گلوگاه مشترک را بررسی کنید؛ حالت failover را هم اندازه بگیرید |
| کندی آماده‌سازی | نصب بسته یا کامپایل موتور ممکن است در جریان باشد؛ پیشرفت و لاگ همان اجرا را بخوانید |

## ۱۳. دامنهٔ تأیید این تحویل

آزمون فیزیکی روی دو Ubuntu 24.04 amd64 نزدیک به هم انجام شده است. نتیجهٔ ایران، شبکهٔ مسدود، NAT، همهٔ توزیع‌ها یا همهٔ چینش‌های جهان اثبات نشده است. مسیر نصب برای چند مدیر بسته وجود دارد، اما شاهد نصب واقعی به محیط آزموده‌شده محدود است.

GRE، IPIP، SIT و VXLAN صرفاً کپسوله‌سازی‌اند و به‌خودی‌خود محرمانگی اضافه نمی‌کنند. برای ترافیک محرمانه، پروفایل رمزنگاری‌شدهٔ مناسب را انتخاب کنید. پنج پروتکل روی یک لینک، پنج لینک مستقل نیستند. گزارش، موفقیت‌ها و تلاش‌های ناموفق را جدا نگه می‌دارد تا نتیجه قابل بازبینی باشد.
