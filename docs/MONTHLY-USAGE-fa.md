# سهمیه مشترک مصرف مشتری

این سند قرارداد پیاده‌سازی است؛ پذیرش نصب پس از انتشار جدا ثبت می‌شود. تمام حساب‌ها و مسیرهای یک فضای مشتری، حتی روی چند سرور مبدأ، یک سهمیه مشترک دارند. محدودیت سرعت، حجم و تعداد اتصال هر مسیر نیز مستقل باقی می‌ماند.

## کار مدیر

در **پنل → مدیریت کاربران و فروش → مصرف مشترک ماهانه** مشتری را انتخاب کنید. مصرف ثبت‌شده، اعتبار در اختیار مسیرها، حجم قابل تخصیص، پوشش حسابداری و تاریخچه دوره‌ها نمایش داده می‌شوند. حجم کل را با واحد بایت/MiB/GiB/TiB و تاریخ پایان به وقت دستگاه خود تعیین کنید. پیش‌فرض دوره تازه۳۰روز است؛ تخصیص، تمدید و دوره جدید فقط توسط مدیر انجام می‌شوند. افزایش سقف، مصرف قبلی را پاک نمی‌کند و ویرایش هم‌زمان با revision کنترل می‌شود.

گزینه **دوره جدید** سوابق قبلی را نگه می‌دارد و سهمیه تازه‌ای آغاز می‌کند؛ ابتدا تمام اعتبارهای باز باید ایمن بسته شوند. کاهش سقف به کمتر از مصرف ثبت‌شده به‌علاوه اعتبار باز رد می‌شود. این عملیات پول جابه‌جا نمی‌کند و رسید پرداخت یا سهمیه خرید قبلی را تغییر نمی‌دهد؛ تخصیص این حجم، مطابق خواسته مالک، مستقل و دستی است.

فعال‌سازی سهمیه مشترک با وجود مسیر فعال فاقد حسابداری رد می‌شود تا بخشی از مصرف بیرون سهمیه نماند. هیچ worker قدیمی خودکار بازسازی یا ری‌استارت نمی‌شود. بازسازی صریح و اختیاری بعدی می‌تواند مسیر تاریخی را وارد حسابداری کند. مسیر تازه، سهمیه فعال همان مشتری را به ارث می‌برد. مشتری در بخش **پلن و دسترسی** مصرف خودش را می‌بیند؛ تغییر سهمیه و دسترسی به مشتری دیگر مجاز نیست.

## معنای مصرف و اعتبار باز

ارسال و دریافت payload پذیرفته‌شده برای عبور از gatewayهای مدیریت‌شده جمع می‌شود. مذاکره SOCKS، پروب، بنچمارک، سربار ISP و ترافیک خارج از این gatewayها داخل این شمارنده نیستند. داده پذیرفته‌شده ممکن است بعداً در انتقال شکست بخورد؛ این شمارنده صورتحساب ISP یا بایت تأییدشده روی سیم نیست. مدیر root روی میزبان خودش می‌تواند نرم‌افزار را دور بزند؛ مقاومت در برابر دست‌کاری root تضمین نمی‌شود.

کنترلر اجرا برای هر درخواست مسیر حداکثر۸MiB اعتبار را اتمی رزرو می‌کند. مجموع مصرف ثبت‌شده و اعتبارهای باز از سقف دوره بیشتر نمی‌شود. worker ابتدا درخواست معلق و اعتبار را ماندگار می‌کند و پیش از انتقال، مصرف مسیر و اعتبار را در یک تراکنش کم می‌کند. تکرار درخواست اعتبار اضافه نمی‌سازد. گزارش مصرف کمی تأخیر دارد؛ اعتبار باز جدا نمایش داده می‌شود و مصرف قطعی نام نمی‌گیرد.

اعتبار استفاده‌نشده پس از حدود۳ثانیه بیکاری، به‌علاوه زمان شبکه/اجرای حلقه، ابتدا روی worker بسته و سپس برگردانده می‌شود. اجاره اعتبار حداکثر۱۰ثانیه است؛ زمان رفت‌وبرگشت و یک ثانیه حاشیه از آن کم می‌شود و ساعت یکنواخت ملاک است. هنگام قطع کنترلر فقط اعتبار رزروشده معتبر قابل مصرف است و پس از انقضای اجاره، payload رد می‌شود. اعتبار سرور قطع‌شده با حدس آزاد نمی‌شود؛ پس از اتصال/ری‌استارت تطبیق می‌شود. توقف مسیر پیش از آزادسازی اعتبار، توقف واقعی worker متعلق به همان مسیر را تأیید می‌کند. دفتر مفقود/خراب به‌جای پاک‌شدن شمارنده خطای قابل بررسی می‌دهد. بنابراین خرابی نود ممکن است موقتاً حجم قابل تخصیص را کمتر کند. پایان دوره، اعتبار تازه را تا تمدید یا شروع ایمن دوره بعد توسط مدیر می‌بندد.

## تنظیم کنترلر اجرا

در env خصوصی **همان کنترلر صادرکننده اعتبار**، متغیر `TP_MONTHLY_QUOTA_URL=https://YOUR_PUBLIC_PANEL/PREFIX/quota/credits` را تنظیم کنید. آدرس باید با HTTPS معتبر و پیشوند واقعی به API همان نصب برسد؛ کنترلر مستقل دیگر نباید از دفتر نامرتبط این نصب استفاده کند. سرور سایت فقط فایل استاتیک و پراکسی دارد؛ دیتابیس، حسابداری و worker روی نودهای جدا می‌مانند.

برای callback یک اعتبارنامه مخصوص همان مسیر از SSH پین‌شده صادر می‌شود؛ نام کاربری، رمز و API key مشتری استفاده نمی‌شوند. TLS اجباری است؛ اطلاعات ورود در URL، query، redirect و پراکسی محیطی رد می‌شوند. بدنه و نرخ درخواست محدودند و caller نمی‌تواند مشتری یا مسیر دیگری را انتخاب کند. token فقط در رکورد رمز‌شده کنترلر و config خصوصی root0600 است و در خروجی عمومی مسیر نمایش داده نمی‌شود.

worker خودش را با `TehNet-TunnelPannel-Gateway/1.0` معرفی و JSON درخواست می‌کند. در آزمایش واقعی، شناسه پیش‌فرض Python روی هر دو نود پاسخ۴۰۳/1010 گرفت و شناسه واقعی سرویس پاسخ۲۰۰. [مستند رسمی Cloudflare درباره بررسی User-Agent](https://developers.cloudflare.com/waf/tools/browser-integrity-check/) این نوع فیلتر را توضیح می‌دهد؛ تنظیم WAF یا TLS ضعیف نشد. وضعیت ارتباط ابتدا ناشناخته است و فقط پس از درخواست واقعی تغییر می‌کند؛ حلقه بیکار، شکست ارتباط را موفق نشان نمی‌دهد.

جدول‌های مرکزی داخل `registry.db` خصوصی و بکاپ استاندارد فضاها هستند. آن را همراه فایل‌های SQLite مصرف روی مبدأها و env/کلید مستقل هر نصب حفظ کنید. بازیابی دفتر توزیع‌شده نیازمند توقف ایمن workerهای شرکت‌کننده است؛ بازیابی صرف کنترلر در حالی که worker اعتبار جدیدتر دارد، می‌تواند اعتبار خرج‌شده را دوباره صادر کند. پذیرش این قابلیت شامل چنین restore زنده‌ای نیست.

API مشاهده مشتری: `GET /api/billing/traffic`. مدیریت: `GET/PUT /api/billing/owner/workspaces/{workspace_id}/traffic` با `quota_bytes`، `ends_at`، `expected_revision` و `new_period` اختیاری. callback خصوصی gateway: `POST /quota/credits`. مشتری غیرفعال/فاقد دسترسی نمی‌تواند اعتبار قابل مصرف بگیرد، اما بستن و گزارش اعتبارهای قبلی برای جلوگیری از حبس مصرف مجاز می‌ماند.
