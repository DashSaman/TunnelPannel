# درگاه سایت و پردازش روی سرورهای جدا

سرور تهران‌نتورک فقط ورودی وب سرویس است. API، دیتابیس و فضای مشتریان، نشست‌ها،
بررسی دسترسی و مصرف، صف کار، امتیازدهی، کامپایل موتور و اجرای تونل روی سرورهای
جدا انجام می‌شود. نصب‌کنندهٔ درگاه هیچ API یا worker پایتون روی سرور سایت نصب
نمی‌کند.

درگاه دو سرویس systemd با کاربر اختصاصی و بدون دسترسی ریشه دارد: اتصال SSH
با کلید میزبان ثابت به API لوپ‌بک کنترلر، و nginx مستقل روی پورت HTTP لوپ‌بک.
nginx اصلی سایت و تنظیمات آن تغییر یا reload نمی‌شوند. فایروال، مسیریابی و
اینترفیس تونلی ایجاد نمی‌شود. سهم CPU هر سرویس۱۰٪ و سقف حافظهٔ SSH برابر۶۴MiB
و nginx برابر۹۶MiB است؛ این‌ها محدودیت اجرایی‌اند، نه ادعای ظرفیت اندازه‌گیری‌شده.
دو پورت با مدیر پورت فعلی و اسکن تازهٔ پورت‌ها، انتشار کانتینر و محدوده‌های
رزروشده انتخاب می‌شوند. اسکن ناقص نصب را متوقف می‌کند. سلامت نیازمند تطبیق
مالک سوکت هر دو سرویس و پاسخ واقعی API کنترلر است.

فقط کلید اختصاصی اتصال به کنترلر روی سایت ذخیره می‌شود. رمز SSH مشتریان و
کلید رمزگذاری نصب، در فضای رمزگذاری‌شدهٔ کنترلر جدا می‌مانند. ثبت access log و
بافرکردن درخواست و پاسخ روی دیسک خاموش است. مجوز حساب و فضای مشتری همچنان در
کنترلر بررسی می‌شود؛ درگاه دسترسی مدیریتی به مشتری نمی‌دهد.

## نصب

پیش‌نیاز: لینوکس systemd، python3، nginx و openssh-client از قبل نصب باشند.
روی کنترلر کاربر SSH اختصاصی بسازید و فقط کلید عمومی درگاه را با محدودیت‌های
`restrict,port-forwarding` و `permitopen="127.0.0.1:API_PORT"` و دستور اجباری
ردکردن نشست ثبت کنید. از کلید root کنترلر استفاده نکنید. کلید میزبان SSH را
مستقل تأیید کنید. مسیرها، حساب یا سرویس متعلق به برنامهٔ دیگر پذیرفته نمی‌شوند.

فرمان تک‌خطی و متغیرهای نصب در [راهنمای انگلیسی](WEB-GATEWAY.md#installation)
آمده‌اند؛ در هر دو محل COMMIT، شناسهٔ ثابت۴۰کاراکتری نسخهٔ تأییدشده را بگذارید.
پورت صریح اشغال یا رزروشده رد می‌شود. اجرای مجدد با همان هویت، فایل‌ها و مالک
سوکت‌ها را بررسی و فقط دو سرویس درگاه را ری‌استارت می‌کند. شروع ناموفق، رسید
PREPARED و فایل‌های خصوصی را برای بررسی نگه می‌دارد و موفق گزارش نمی‌شود.

پورت و وضعیت در `/etc/tunnelpannel-web-gateway/receipt.json` است. برای تست
خصوصی، SSH local forward به پورت HTTP لوپ‌بک باز کنید و `/portal` را ببینید.
اتصال عمومی آینده باید HTTPS را در پراکسی فعلی سایت خاتمه دهد. این نصب‌کننده
دامنه، پورت عمومی یا تغییر تنظیمات سایت انجام نمی‌دهد و اطلاعات مشتری را کپی
نمی‌کند.

## مرز فروش

حساب‌ها، سقف فضای مشتری، مصرف روزانهٔ روش‌ها و اشتراک آزمایشی روی کنترلر جدا
بررسی می‌شوند. اشتراک sandbox به معنی دریافت پول نیست. قیمت‌گذاری به‌ازای
استفاده، رزرو اعتبار، تسویه/بازپرداخت و درگاه پرداخت باید پیش از دریافت پول
به‌صورت مستقل پیاده‌سازی و تست شوند. نصب پراکسی به‌تنهایی پرداخت یا ورود مشترک
با سایت را فراهم نمی‌کند.

سرورهای کنترلر و نودها تا وقتی اطلاعات مشتری یا تونل فعال دارند باید باقی
بمانند. انتقال ورودی سایت، مهاجرت این منابع نیست. دیتابیس کنترلر و کلید نصب
جداگانه و نیز کلید اختصاصی درگاه را خصوصی بکاپ بگیرید و بازیابی رمزگذاری‌شده
را تطبیق دهید. برای افزودن درگاه، بکاپ را روی فضای زندهٔ تونل‌ها restore نکنید.
