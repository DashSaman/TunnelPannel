# Mesh implementation plan

Spec: ../specs/2026-10-15-mesh.md

1. Customer isolation: separate SQLite workspace databases, owner-only registry/key lifecycle, scoped request factory, captured background factory, protected data routes, cross-customer API tests.
2. Campaigns and recommendations: durable directed route jobs, real pair runner integration, restart/cancellation handling, measured qualification, deterministic diverse top five, ordered custom selection and limits. Tests include three simulated nodes and real two-node campaigns.
3. Persistent route execution: independently owned warm tunnels and forwarding endpoints, data-plane health, hysteresis, manual pin/order, durable reconciliation, cleanup, physical-host locking and prefix allocation. Prove actual traffic switches during failures and survives worker restart.
4. Engine audit and additions: persist accessible-repository audit, implement finite genuine missing profiles/compositions, run real positive/negative/recovery tests on supplied pair, retain unsuccessful receipts.
5. Mesh UI and documentation: customer-scoped onboarding/campaign/route controls, RTL/LTR, no CDN, honest metrics/capabilities, bilingual guide and screenshots.
6. Release: fresh regression suites, live two-node/API/browser/lifecycle validation, publish exact immutable source, install pinned release on both nodes, deliver checksums, evidence and one-line install.

Interfaces: request-scoped factory -> all existing routers and background benchmark threads; campaign job -> BenchmarkRunner receipts -> recommendation selector -> route deployment; route deployment -> resource journal -> health/switch worker. Never pass live SQLAlchemy sessions across threads. Preserve historical jobs and installation secrets.
