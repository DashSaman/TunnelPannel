# Administrator migration of registered legacy gateways

Owner explicitly requests browser-based administrator migration, preservation of settings, two-node acceptance and website/repository publication. Execute within this authorization. Existing originals are already enrolled: do not migrate/rebuild them again. New QA routes only.

Extend the existing owner console and privileged migration routine. The owner selects a customer and a registered live route; a fresh preflight verifies enabled workspace, controller callback, uncapped pool, encrypted/live configuration, owned gateway path/unit, current PID, healthy idle state and scope. Persist a short-lived server-side operation ticket, never accept config/PID/root-path/token overrides from the browser. Include already-enrolled and unavailable routes with accurate status.

Execution is an asynchronous durable operation, globally bounded to one migration per installation. Atomically claim the prepared ticket; repeated submission returns the same running/completed result. Recheck under existing admission/route/host leases. Before dispatch, make online encrypted controller/registry/target database snapshots with the installation key kept separately by normal installation backup. Source cutover retains its existing root-private rescue/config/usage receipts. Keep the same gateway-only migration and nonce measurement. Public reports are allowlisted and errors sanitized.

After interruption/failure, preserve pending intent and require a fresh preflight; never auto-restart/retry/cancel a gateway on application startup. Recovery rechecks an orphan under its process-safe lease and commits before release. An encrypted operation receipt is committed atomically with route enrollment; if only the later ticket completion was lost, recovery copies that already-committed result without SSH or a new cutover. Otherwise a new prepared operation can resume the encrypted pending candidate and adopt an already-running metered worker without another restart. Disabling a workspace still blocks enrollment/credits; existing paid/unpaid state and all member configuration/processes remain unchanged.

Endpoints stay under `/api/billing/owner/` and require system SUPER_ADMIN, existing CSRF/origin rules and no-store responses. Customer SUPER_ADMIN/operator/viewer cannot access them. UI FA/EN offers preflight, explicit execution, refresh and same-route fresh recovery; it displays usage policy, settings, measured gap and pending/blocked reasons without credentials. It neither exposes download of private backups nor accepts shell input. This migrates panel-owned routes, not arbitrary foreign tunnels.

Verify API isolation, CSRF, stale/tampered tickets, duplicate/concurrent submit, restart orphan handling, private snapshot roundtrip, pending recovery, safe reports and conservation. Publish an immutable tree with expected-head lease and green CI before upgrades. Fresh per-install encrypted rollout backups; preserve original two gateways/member identities. Run new opposite-source QA through the public admin API, real transfer/accounting and UI, then clean only owned QA. Static website only, PR2 unmerged, heartbeat paused, no payment/account changes.
