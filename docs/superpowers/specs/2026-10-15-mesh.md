# Customer-scoped tunnel mesh

The owner authorizes implementation, disposable-node tests and publication. Work continues inline without approval checkpoints. The two supplied nodes are the only authorized real infrastructure; no claim of Iran or intercontinental validation is possible from this pair.

## Required behavior

Customers register pinned SSH nodes using IP, user and password. A campaign tests every directed pair (or explicit requested routes), including supported compositions. Per-route recommendations contain up to five measured, qualified methods by latency, jitter, loss, throughput, recovery and failure-domain diversity. Fewer qualified methods must remain fewer. Manual ordered selections and larger counts are supported within configurable entitlements.

Each selected route has owned persistent tunnels, independent forwarding entry point, actual data-plane health and automatic/manual failover. Many destinations coexist without replacing the management/default route. Endpoint failure requires another destination; protocol redundancy to one endpoint is not endpoint redundancy. Transport capabilities are explicit: TCP/SOCKS forwarding is not advertised as arbitrary full-IP VPN.

Customer workspaces use separate databases and hashed scoped API keys. No customer can read, cancel, deploy or resolve another customer's nodes/jobs/routes. Background execution captures the initiating database. The owner registry is not exposed through customer permissions. Credentials stay encrypted; raw tokens are returned only once. Future billing can change entitlements, but payment processing is outside this request.

## Repository review and additions

All 33 repositories accessible to the owner's connection were reviewed through manifests and README, with targeted source reads for tunnel engines. t4 is a PBX application and supplies no tunnel. t6 and HajSaman share WireGuard over SIT already implemented here; do not count aliases as new tunnels or publish private source. GoldWaterTunnel adds a WaterWall Reality/VLESS profile; WaterWall-H provides independently buildable paired transports. Hedioum alternate mimics, VMess, AnyTLS, ShadowTLS, NaiveProxy and OpenConnect are candidates. Research-only/proprietary entries do not establish implementation. Import only source-pinned, genuinely paired, measured implementations; retain blocked/failing outcomes explicitly. Compositions are bounded typed templates, never an arbitrary Cartesian product.

## Safety and evidence

Preserve both installed panel secrets, tokens and history. Serialize physical-host mutations even if registered under different IDs/workspaces. Allocate conflict-free ports/interfaces/prefixes; retain ownership journals and verified cleanup. Never flush host firewall state or replace default routes. Existing 82-method evidence remains historical evidence, not proof of new functionality. New release requires fresh software checks, real paired campaign/failover/restart tests, browser verification, bilingual docs, pinned one-line installer and publication. Multi-node graph behavior can be simulated but must be distinguished from physical geographic evidence.
