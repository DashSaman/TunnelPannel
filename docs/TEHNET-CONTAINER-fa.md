# کانتینر درگاه وب روی سایت موجود

ورودی عمومی پنل می‌تواند در `https://tehnet.ir/tunnels/` و داخل کانتینر nginx مستقل اجرا شود. این کانتینر فقط رابط ایستا و پراکسی است؛ API، حساب‌ها، دیتابیس مشتری، سهمیه، صف کار، کامپایل و تونل روی کنترلر و نودهای جدا می‌مانند. سوکت Docker، دیتابیس کنترلر، رمز مشتری یا کلید خصوصی SSH در کانتینر mount نمی‌شود.

بسته را روی رایانهٔ مدیریت/ساخت از سورس بازبینی‌شده با `scripts/container_web_gateway.py` بسازید؛ [فرمان و جزئیات انگلیسی](TEHNET-CONTAINER.md). پورت باید با مدیر پورت اصلی و اسکن تازهٔ کامل شامل انتشار کانتینر، رزرو اپراتور و تخصیص‌های قبلی انتخاب و درست قبل از شروع دوباره بررسی شود. تصویر nginx باید به digest ثابت متصل باشد. مسیر خروجی موجود پذیرفته نمی‌شود. لینک صفحه‌ها، فایل‌ها، API، نتیجهٔ کمپین و دعوت همگی زیر پیشوند برنامه می‌مانند. اسکریپت‌های inline به فایل جدا منتقل می‌شوند تا سیاست `script-src 'self'` قابل اجرا باشد. نصب قدیمی در ریشه نیز سازگار می‌ماند.

کانتینر با UID101، فایل‌سیستم فقط‌خواندنی، حذف همهٔ capabilityها، no-new-privileges، tmpfs محدود، سقف ۳۲ پردازش، ۹۶MiB RAM و ۰٫۲۰ CPU اجرا می‌شود. شبکهٔ host برای دسترسی به SSH forward موجود روی loopback انتخاب شده؛ این انتخاب namespace شبکه را جدا نمی‌کند. پورت HTTP خود کانتینر نیز فقط loopback است و پراکسی HTTPS فعلی فقط `/tunnels/` را منتشر می‌کند. کلید SSH داخل کانتینر نیست و capability ساخت اینترفیس ندارد.

پیش از انتشار، بکاپ خصوصی تنظیمات/منوی سایت و دیتابیس آن، دیتابیس کنترلر و env/کلید نصب مجزا بگیرید. شناسه و زمان شروع کانتینرهای قبلی، سرویس‌ها و هش تنظیمات/PID تونل‌های فعلی ثبت شود. تا پایان کارهای بنچمارک و deployment کنترلر صبر کنید؛ برای این تغییر کار مشتری لغو و worker تونل فعلی ری‌استارت نشود.

روی کنترلر `TP_PUBLIC_ORIGIN=https://tehnet.ir` و اعتماد forwarded header فقط برای `127.0.0.1` تنظیم می‌شود. پس از تخلیه کارها فقط API ری‌استارت می‌شود؛ سورس، کلید و دیتابیس حفظ می‌شوند. پراکسی HTTPS باید Host، پروتکل و آدرس کلاینت را خودش تعیین کند. درگاه پیشوند را برای API حذف می‌کند، Origin و CSRF را نگه می‌دارد و کوکی Secure/HttpOnly/SameSite را به `/tunnels/` محدود می‌کند. پس از این تغییر، ورود با کوکی در localhost دیگر مبدأ اصلی نیست.

بسته در release تازه و متعلق به همین برنامه کپی، Compose و nginx داخل کانتینر اعتبارسنجی و فقط همان سرویس شروع می‌شود. location از include مستقل در بلاک TLS سایت افزوده شود؛ پیش از نوشتن هش تنظیمات جاری و پیش از reload آرام، `nginx -t` بررسی شود. فایل‌های قبل برای rollback نگه داشته شوند و تغییر اپراتور دیگر بازنویسی نشود. اتصال SSH خصوصی و درگاه HTTP قبلی می‌توانند برای عیب‌یابی باقی بمانند.

پس از موفقیت HTTPS، فایل‌های رابط و ورود، فقط یک لینک «مدیریت تونل» با API منوی وردپرس به منوی اصلی فعلی اضافه می‌شود. شناسه، ترتیب، URL و والد تمام گزینه‌های قبلی حفظ می‌شوند. منوی دسکتاپ و موبایل از همین منو استفاده می‌کنند. حساب وردپرس، SSO یا پرداخت به این معنی پیاده نشده است.

پذیرش باید آدرس واقعی HTTPS، چهار صفحه و فایل‌ها، ورود و خواندن نود/تاریخچه با تفکیک فضای مشتری، مسیر/فلگ کوکی، رد Origin خارجی و CSRF نامعتبر، رد API بدون ورود، فارسی/انگلیسی و منوی موبایل، و حفظ سرویس‌ها و تنظیمات/PID تونل‌ها را پوشش دهد. فقط شواهد بدون اسرار در Git قرار می‌گیرد؛ بکاپ‌ها و اطلاعات ورود خصوصی می‌مانند. این استقرار مبلغی از کاربر دریافت نمی‌کند.
